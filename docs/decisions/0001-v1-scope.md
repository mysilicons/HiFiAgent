# ADR 0001: 冻结 V1 范围

## 状态

已接受

## 日期

2026-06-25

## 背景

基因组组装工作流可能迅速扩展到支架构建、分相、注释、参数搜索和网络平台关注点。HiFi Agent V1 旨在作为一个专注、可重复的项目，展示 PacBio HiFi 质量控制、hifiasm 执行、多指标组装评估、受限代理控制和可解释报告。

系统还需要明确的安全边界：一个可选的 LLM 层可能有助于解释和排序合法决策，但它不得生成任意命令或不支持的组装器参数。

## 决策

V1 将支持每次运行一个明确的样本、PacBio HiFi FASTQ/FASTQ.GZ 输入、真核基因组组装和 hifiasm HiFi-only contig 组装。项目将使用 Linux、Nextflow DSL2、Python、结构化 JSON 模式、审核的 YAML 规则和名为 `hifiAgent` 的 conda 环境。

V1 将排除 Hi-C、三联体分型、ONT 超长辅助组装、自动多倍体优化、染色体级支架构建、基因组注释、重复注释、无界参数搜索和直接 LLM shell 执行。

自动 hifiasm 参数处理仅限于白名单：

- `threads`
- `output_prefix`
- `purge_level`
- `purge_similarity`
- `hom_cov`
- `disable_post_join`

第一次组装运行始终是基线 hifiasm，除了线程数和安全输出前缀外，不进行生物参数更改。

## 影响

积极方面：

- 范围对于 V1 实现仍然是可实现的。
- 决策是可测试和可解释的，无需 LLM。
- 失败或不确定的生物证据可以产生安全停止状态，而不是强制优化。
- 基准测试可以专注于规则、解析器、状态转换和可重复性。

权衡：

- V1 不会产生染色体级组装。
- V1 不会优化复杂的多倍体或多技术组装案例。
- 一些真实数据集将被标记为超出范围，即使 hifiasm 技术上可以处理它们。
- 用户必须提供明确的输入和元数据，而不是依赖自动发现。

## 后续工作

- 第 1 阶段：创建 Python 项目骨架和代码质量工具。
- 第 2 阶段：实现配置模式和输入验证。
- 第 3 阶段：使用 Java 17-24 和 `-resume` 验证本地 Nextflow 执行。
- 第 8 阶段：实现第一个可审核的规则目录。
